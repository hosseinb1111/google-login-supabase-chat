# Free & Complicated Messenger 💬

A tiny realtime chat app — Google sign-in, replies, edits, deletes, emoji
reactions, and a light/dark theme — built as three static HTML files with
[Supabase](https://supabase.com) for auth, storage, and realtime updates.
No build step, no framework, no backend to host.

## Structure

| File         | Purpose                                                             |
|--------------|----------------------------------------------------------------------|
| `index.html` | Entry point. Redirects straight to `login.html`.                    |
| `login.html` | Google OAuth sign-in screen. Skips ahead to `chat.html` if you already have a session. |
| `chat.html`  | The chat itself: message list, composer, replies, edits, reactions, realtime updates. |

## Setup

### 1. Create a Supabase project

Create a free project at [supabase.com](https://supabase.com/dashboard) and
grab its **Project URL** and **anon/publishable key** from
*Settings → API*.

### 2. Create the `messages` table

Run this in the Supabase SQL editor:

```sql
create table messages (
  id bigint generated by default as identity primary key,
  username text not null,
  text text not null,
  created_at timestamp with time zone default now(),
  reply_to bigint references messages(id),
  reactions jsonb default '{}'
);

-- Row Level Security: required, since the anon key is public.
alter table messages enable row level security;

create policy "Anyone signed in can read messages"
  on messages for select
  to authenticated
  using (true);

create policy "Anyone signed in can insert messages"
  on messages for insert
  to authenticated
  with check (true);

create policy "Anyone signed in can update messages"
  on messages for update
  to authenticated
  using (true);

create policy "Anyone signed in can delete messages"
  on messages for delete
  to authenticated
  using (true);
```

Then turn on Realtime for the table: **Database → Replication →
`messages`**, toggle it on.

### 3. Enable Google sign-in

In **Authentication → Providers**, enable **Google** and follow Supabase's
guide to set up an OAuth client in the Google Cloud console. Add your app's
URL (e.g. `http://localhost:5500` while developing) to the provider's
**Redirect URLs**.

### 4. Add your credentials

Open `login.html` and `chat.html` and replace `SUPABASE_URL` and
`SUPABASE_ANON_KEY` near the top of each `<script type="module">` block
with your own project's values. **Keep both files using the same values** —
the app is unauthenticated otherwise.

> The anon/publishable key is meant to be public. It's safe to ship in
> client-side code as long as Row Level Security policies (like the ones
> above) control what that key can actually read or write.

### 5. Run it

These are plain static files — serve them with anything, e.g.:

```bash
npx serve .
# or
python3 -m http.server 5500
```

Then open `index.html` in a browser.

## Notes

- Usernames are taken from the signed-in Google account's display name (or
  email as a fallback) — there's no separate username field.
- Message text is HTML-escaped before rendering, but this is still a demo
  app: don't point it at untrusted users without hardening the RLS
  policies above further (e.g. restricting edit/delete to the message's
  own author).
- If the chat screen shows a "database table missing" message, it's
  walking you through the same SQL from step 2 above.
